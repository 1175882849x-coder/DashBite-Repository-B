**Proposed requirements and design**

   - Add `healthcheck` only to the `dashboard` service in `compose.yaml`.
   - Probe `http://127.0.0.1:8501/_stcore/health` using Python’s standard library, avoiding an additional curl installation.
   - Require HTTP 200; connection errors, timeouts and other statuses must return a nonzero exit code.
   - Start with a 30-second startup grace period, 10-second interval, 3-second request timeout, 5-second Docker timeout and three retries. Adjust only if measured startup behavior warrants it.
   - Keep the probe in Compose because the shared image also runs four services without an HTTP server.

   Streamlit documents this endpoint for container health checks. [Streamlit Docker guide](https://docs.streamlit.io/deploy/tutorials/docker)

   **Document the limitation explicitly:** healthy means Streamlit’s HTTP health endpoint responds. It does not establish that dashboard pages render correctly, data is fresh, training succeeds, predictions exist, or the other services work. Docker health status also does not itself restart an unhealthy container. [Docker service reference](https://docs.docker.com/reference/compose-file/services/#healthcheck)

2. **Isolated containerized tests**
   - Add a **standalone** `compose.test.yaml` containing one test service.
   - Give it no runtime volume, host data bind mount, published port, or runtime service dependency.
   - Run the complete suite with `python -m pytest`; propagate its exit code.
   - Continue using `tmp_path` and explicit `base=tmp_path`, which the existing file-writing tests already use.
   - Remove the disposable container after each run.

   Proposed commands, run from Repository B:

   ```powershell
   docker compose -p dashbite-b-tests -f compose.test.yaml config --quiet
   docker compose -p dashbite-b-tests -f compose.test.yaml build tests
   docker compose -p dashbite-b-tests -f compose.test.yaml run --rm --no-deps tests
   ```

   Compose supports this one-off execution and cleanup pattern. [Docker Compose run reference](https://docs.docker.com/reference/cli/docker/compose/run/)

   **Tradeoff:** a separate file repeats a little configuration, but makes isolation easier to audit than a test service inheriting the runtime anchor. Do not combine it with `compose.yaml` as an override.
